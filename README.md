# INDICE Platform homepage

Responsive, pre-rendered HTML/CSS/JavaScript. No backend or deployment configuration. All substantive content and product presentations remain available without JavaScript; the Cases technical-reference diagrams optionally load Mermaid from a CDN.

## Run and verify

Open `index.html` directly, or run `python -m http.server 8080` and visit `http://localhost:8080`.

```sh
npm run build   # regenerate index.html after editing data or the template
npm run check   # syntax, copy, structure, assets, anchors and ARIA references
npm test        # scroll-story behavior tests with a mock DOM
```

Run `npm install` before building. Node 22.12 or newer is recommended for development checks.

Cases has one internal page: `cases-reference.html`, generated from the supplied `cases-product.md`. The homepage carousel and Suite panel both link directly to this technical reference. Features labelled next release remain identified as such. Article layout lives in `css/cases-article.css`; tables and code scroll independently on small screens. `js/cases-article.js` tracks active sections and enhances diagrams with Mermaid 11.12.1 from jsDelivr; without JavaScript or network access diagram source remains readable. Run `npm run build` after editing the Markdown source.

## Design versions

Three versions of the homepage share the same three pillars, product logos and facts. A ribbon at the top of each page (`css/design-ribbon.css`, markup from `designRibbon()` in `scripts/shared.js`) switches between them and the three homepage proposals described below. The ribbon stays one line (32px) high, so it never covers the original homepage's fixed logo: it has no visible scrollbar, the "Design preview" label is hidden up to 860px wide, and up to 1060px wide the proposal buttons drop their concept names ("Proposal A"). On phones the row scrolls sideways, and each proposal page brings its own button into view.

| Page | Design | Source |
|---|---|---|
| `index.html` | Original: warm paper, Manrope, teal accent | `scripts/render.js`, `js/data.js` |
| `terminal.html` | Terminal: dark IDE shell with explorer, file tabs, product tabs, command palette (Ctrl/Cmd K), status bar and a Risk aggregation demo. JetBrains Mono, phosphor green | `scripts/render-terminal.js`, `css/terminal.css`, `js/terminal.js` |
| `blueprint.html` | Blueprint: cobalt engineering drawing with a layered stack diagram that traces each product's dependencies, parts list, general notes, accordion datasheets, dependency matrix and title block. Space Grotesk and JetBrains Mono, yellow | `scripts/render-blueprint.js`, `css/blueprint.css`, `js/blueprint.js` |

- `scripts/tech-content.js` holds the engineering copy both new designs render: stack, hosting, endpoints, code samples and extension points taken from the Cases, IAM, Messaging and Risk product documents, the platform pillars document and the public `indice-co` repositories. Features the documents mark "next release" are excluded. Code samples are quoted verbatim and highlighted at build time by `scripts/highlight.js`; a test checks the highlighted text equals the source.
- Pillar text comes from `js/data.js`, so editing it updates all three versions. Product logos are the existing `assets/logos/*` files; Terminal and Blueprint seat the full logos on light plates because the wordmarks are dark.
- Missing assets and links are explicit placeholders (dashed, labelled `placeholder`, `role="link" aria-disabled="true"`, no `href`): the demo request, the Agents and Workers logos and documents, and the technical references of IAM, Messaging and Risk. Real links go to the `indice-co` GitHub organisation, the NuGet profile, the `@indice/ng-*` npm packages and `cases-reference.html`.
- Both designs are complete without JavaScript. Hiding rules only apply behind classes the scripts add (`tabs-ready`, `reveal-ready`, `bp-anim`), so a failed script load leaves every product and sheet visible. Blueprint datasheets are native `<details>` elements that start closed and open on click or from a `#ds-<product>` link. Motion respects `prefers-reduced-motion`.
- Each suite product in Terminal and Blueprint has a UI screenshot carousel placeholder (`screenshotCarousel()` in `scripts/shared.js`, styles in `css/carousel.css`, controls in `js/carousel.js`). Without JavaScript it is a scroll-snap strip. Slide titles come from the product's first three highlights. To use real screenshots, replace a slide's `.shot-frame` with an `<img>` that has alt text.
- Fonts live in `assets/fonts/` with their SIL OFL licences (JetBrains Mono, Space Grotesk).
- `npm run build` regenerates all three pages; `tests/variants.test.js` fails if `terminal.html` or `blueprint.html` are out of date. Any deployment step that copies `index.html` must also copy these two pages.

Features the documents mark "next release" are excluded.
- **Solutions slider (Proposal A only):** `scripts/showcase-markup.js` renders the slider for `index.html` and Proposal A from one template, so its structure, ids and data attributes stay identical, and `js/showcase.js` runs unchanged. `scripts/proposals/showcase-css.js` copies every slider rule from `css/styles.css` into `css/proposals/showcase.css` (generated; do not edit). `css/proposals/showcase-theme.css` maps the slider's colour tokens to the proposal's light or dark tokens. Proposal styles live in an `@layer`, so the unlayered slider styles win inside the slider; Graphite's restyle (glass navigation and chapter card, rounded screens, a glow in the active product's colour) is the unlayered block at the end of `proposal-a.css` and changes surfaces only, not layout or behaviour. - **Themes:** each proposal has its own default (A and B light, C dark) and remembers the visitor's choice separately in `localStorage` (`indice-proposal-a-theme`, `indice-proposal-b-theme`, `indice-proposal-c-theme`). Dark-theme product logos are generated into `assets/logos/on-dark/` by changing only the two wordmark colours of the supplied SVGs; the INDICE wordmark is drawn in the current text colour.
- **Behaviour:** `js/proposals/common.js` handles theme controls, the back-to-top button (shown after the first screen, hidden while the slider owns the viewport), sticky page chrome around the slider, reveals, parallax (`data-parallax`), pointer effects (`data-spotlight`, `data-magnetic`, `data-tilt`, Proposal C's `data-cursor` ring), scroll-linked marquees (`data-velocity`), text scrambles (`data-scramble`), menus, dialogs, tabs, the screen galleries and viewer, expanders, reading progress and section highlighting. Content stays readable without JavaScript (expandable panels stay open), and motion is skipped for `prefers-reduced-motion`. Demo buttons stay unwired, as on the original homepage.
- **Links:** Cases links to `cases-reference.html`. IAM, Messaging and Risk have no internal page yet, so their "Technical details" links go to the solution on the same page: the `#spec-<id>` tab in Proposal A, and the Architecture part of the entry or row (`#spec-<id>-architecture`) in Proposals B and C, whose "Learn more" links open `#spec-<id>`. The slider keeps their disabled Explore buttons.
- **Fonts:** Manrope (`manrope-variable.ttf`) and JetBrains Mono (`jetbrains-mono-variable.woff2`), already in `assets/fonts/` with their SIL OFL licences.
- `npm run build` regenerates the proposals, the slider and screen stylesheets and the dark logos; `tests/proposals.test.js` fails if any are out of date. A deployment that copies `index.html` must also copy the three proposal pages, `css/proposals/`, `js/proposals/` and `assets/logos/on-dark/`.
