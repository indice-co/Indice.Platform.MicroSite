# INDICE Platform

Open-source .NET and Angular libraries, four products built on them that you deploy on your own infrastructure, and the engineers who integrate and maintain them.

## Foundation

Open-source .NET libraries on NuGet and Angular libraries on npm give every product the same ASP.NET Core, EF Core and OpenID Connect base. You extend tested packages instead of rebuilding common infrastructure, and deploy them in your own environment.

### Practices

Principles

  • Every product is a deployed system, not a SaaS: your databases, keys, queues, delivery accounts and operations.
  • Extension points are C# interfaces, not a DSL. Extensions run in your host and debug with the rest of your app.
  • Every seam ships a safe default, so a fresh host runs before any of them is implemented.
  • Everything that can be a setting is a setting. Code is for the seams.
  • Each product ships an Angular admin SPA that your API host serves in-process; there is no separate frontend deployment.
  • Each store has its own EF Core migrations history; a production host brings its own migrations assembly.

## Suite

Cases, IAM, Messaging and Risk are ready-made products that you host inside your own ASP.NET Core applications, each with its own SQL Server database, APIs and embedded Angular admin UI. Adopt one on its own or combine several, and extend them with your own code.
Cases IAM Messaging Risk Agents Workers

Case management and business workflows

base unit · case typeTechnical reference →

A case type is a JSON Schema form, a set of checkpoints and an Elsa workflow that decides who acts next. Customers and back-office staff work on the same record through two APIs.

What it does

  • Process as dataA new process is a case type (schema, layout, checkpoints) plus a workflow, not a code change. Workflows are edited and published from the designer at /workflow without a redeploy.
  • Two views, one recordmy/* serves customers, manage/* serves staff. Private checkpoints stay internal; the customer sees the last public checkpoint and the published data version.
  • Actions come from the workflowGET manage/cases/{id}/actions asks the workflow which blocking activities are waiting (assign, edit, approve, custom actions). The SPA renders exactly those.
  • Three-layer access controlRoles (CasesUser, CasesManager, CasesAdministrator), record-level access rules, and ownership. Four-eyes approval is a workflow activity: Block previous approver.
  • Everything is a rowCheckpoints, data versions, comments and approvals live in CasesDb; the timeline is a query. A PDF per case type renders from a Razor template.

Identity and access management

base unit · userTechnical referenceplaceholder

ASP.NET Core Identity stores the users and Duende IdentityServer speaks OIDC / OAuth2. Indice adds the grants, MFA, devices, audit and UI. Workforce, partners and customers sign in through one pipeline.

What it does

  • One sign-in pipelinePassword or external provider (Apple, Google, Microsoft, Facebook, GovGr), then MFA, then the post-login validation activities, then tokens.
  • Custom grantsFive grant types on top of the standard flows: totp, mfa, device_authentication, delegation and urn:indice:guest. The same IExtensionGrantValidator seam is open to you.
  • Six MFA methodsSMS, Email, Viber, Authenticator app (TOTP), Trusted device (push approval over the /mfa SignalR hub) and FIDO2 / WebAuthn.
  • Devices and sessionsA new device becomes trusted only after TrustActivationDelay (48 hours in the template). Server-side sessions are rows you can revoke; EnforceSingleActiveSession ends older sessions.
  • Hardening and audit20 per-endpoint rate-limit rules, reCAPTCHA v3 with v2 fallback, lockout, password history. Two audit trails: sign-in logs with impossible-travel checks, and activity logs.

Multichannel campaigns and notifications

base unit · campaignTechnical referenceplaceholder

A campaign fans out to Inbox, Push, Email and SMS according to its settings and each recipient’s preferences. Transactional messages (OTPs, receipts, alerts) run through the same pipeline.

What it does

  • One campaign, four channelsMessageChannelKind is a [Flags] enum: Inbox 1, PushNotification 2, Email 4, SMS 8. Content is authored per channel and rendered per recipient with Handlebars (Full, Partial and Layout templates).
  • Preference-aware deliveryChannels are resolved per recipient when the campaign is sent: campaign channels, narrowed by the recipient’s preference for the message type, minus what they cannot receive. IgnoreUserPreferences covers true system messages.
  • API enqueues, worker deliversThe API accepts and queues; the worker resolves, renders and sends. Systems send through the send API under the narrower messages:send scope and get 202 Accepted.
  • Vendors are configurationEmail: SMTP, SendGrid, SparkPost, Brevo, Azure Communication Services. SMS / Viber: Yuboto, Yuboto Omni, Apifon, Twilio, Vonage, SmsUp, KapaTEL, Mstat. Push: Azure Notification Hubs to APNS and FCM v1.
  • Analytics off the hot pathEvents are queued and batched into MessageEvent records. KPIs: Reached, Engaged, Acted, Coverage. Click tracking rewrites links to /_tracking/… and redirects.

Risk assessment for transactions and activity

base unit · risk ruleTechnical referenceplaceholder

A risk rule is a C# class that looks at an operation. Its thresholds are settings operators change at runtime. POST api/risk returns one score and one level (None, Low, Medium, High) with a reason per rule.

What it does

  • Policy as code plus dataDetection logic is reviewed, versioned and unit-tested like the rest of your software. Thresholds, lists and switches live in RiskDb and hot-reload (every 5 seconds in the template) without a redeploy.
  • Configurable scoringLevel ranges are configuration (template: 0, 1–1000, 1001–2000, 2001–3000). Aggregation is Sum, where risk accumulates, or Maximum, where the worst rule decides. Overlapping ranges stop the host at startup.
  • Verdicts you can explainEvery assessment is stored with its input and per-rule score, level and reason, whether or not the operation goes ahead. A recorded event carries the ResultId of its verdict.
  • History for rulesPOST api/risk/events records what happened. IRiskEventStore.GetList(subject, names, dates, filters) gives rules velocity, frequency and first-time-beneficiary checks.
  • Offline geolocationMaxMind GeoLite2 databases ship with the product. The IP address resolves to country and coordinates inside the host; nothing leaves it.

### How the products connect

  • Cases · Messaging · Risk→IAM

    Sign in with tokens issued by IAM. The IAM template seeds the cases, messages, messages:send, media and agents API resources so the other products authenticate against it.

  • Cases→IAM

    UseContactProviderIdentity searches customers in your Identity Server.

  • Messaging→IAM

    UseIdentityContactResolver pulls contact data, consent, locale and preferences from Identity.

  • Calling apps→Risk

    Web banking, mobile, payments and identity flows call POST api/risk before the operation. Risk returns a level; the app decides, for example Medium → step-up authentication.

## Expertise

Our engineers build custom applications on the platform and integrate its products with your existing systems, APIs and identity providers. After go-live we keep your solution current with new features, CVE patching and direct support from the INDICE engineering team.

Software development

Custom applications and extensions on the platform libraries, built around your processes and requirements.

#2

Integration

Suite products connected to your existing systems, APIs, identity providers and delivery accounts.

#3

Ongoing support

New features, regular security updates (CVE patching) and direct technical assistance from the engineers who maintain the code.
